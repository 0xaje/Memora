# MEMORA — PHASE 3: OPERATIONAL INTELLIGENCE & REASONING

## 1. Executive Summary

Memora has advanced from simple memory retrieval into a structured **Operational Intelligence Layer**.

The foundational product thesis remains:
> **"What happened before changes what Memora does now."**

In Phase 3, this thesis is enriched: historical memory does not simply flag recurrence; it actively diagnoses why previous operational actions failed, maps multi-dimensional patterns, flags unresolved operational risk boundaries, translates institutional lessons into forward guidance, and explicitly separates facts, inferences, historical precedent, and actionable recommendations in a typed evidence taxonomy.

All reasoning remains **100% deterministic and evidence-bound**. No LLM is permitted to select risk levels, override baseline policies, or hallucinate operational precedent.

---

## 2. Core Architectural Pillars

### 2.1 Structured Evidence Taxonomy
Every operational statement output by Memora belongs to one of five mutually exclusive classes:
- **`CURRENT_FACT`**: Extracted directly from operator input (location, entity, timestamp, license plate, observable indicators). Source: Operator Input.
- **`HISTORICAL_FACT`**: Retrieved directly from Sibyl Memory records (incident IDs, past actions taken, observed outcomes). Source: Sibyl Memory.
- **`INFERENCE`**: Deterministic correlation between current facts and historical memory (recurrence count, failure pattern, temporal escalation). Source: Deterministic Pattern Inference.
- **`UNKNOWN`**: Explicit missing operational information necessary for complete risk resolution (unverified driver, unknown destination, missing credentials). Source: Fact Extractor.
- **`RECOMMENDATION`**: Actionable guidance generated by the decision engine (decision shift, escalation directive, required protocol adjustment). Source: Memora Decision Engine.

### 2.2 Rich Deterministic Fact Extraction
The extraction pipeline (`memora/intelligence/extractor.py`) parses natural language operational reports into structured attributes without LLM nondeterminism:
- **Temporal Window**: Identifies approximate times (e.g., `14:30`, `morning shift`, `yesterday at 22:00`).
- **Duration**: Detects lingering or surveillance duration (e.g., `for 45 minutes`, `lingering for 3 hours`).
- **Vehicle & Entity Attributes**: Identifies vehicle models, colors, license plates, and personnel descriptions.
- **Reporter Attribution**: Identifies reporting officer, guard, or department (e.g., `reported by Officer Miller`, `per Guard Station B`).
- **Explicit Unknowns**: Surfaces operational blind spots (driver not identified, cargo manifest absent, destination unspecified).

### 2.3 Multi-Dimensional Pattern Analysis
Rather than simple string matching, `memora/intelligence/comparator.py` evaluates multiple dimensions:
- **Temporal Recurrence**: Detects multiple sightings or events occurring across operational windows.
- **Failed Mitigation Patterns**: Identifies prior tactical responses that failed to prevent recurrence (e.g., passive monitoring without physical verification).
- **Location Relevance Guardrails**: Enforces strict operational boundaries. Incidents at Gate 3 do NOT escalate routine maintenance trucks at Gate 7 unless explicitly linked.
- **Resolved Precedent Separation**: Historical incidents marked resolved do NOT trigger unresolved risk escalations, while still preserving institutional knowledge.

### 2.4 Failed Mitigation Diagnosis & Actionable Lessons
When historical memory indicates an unresolved outcome with a prior action:
1. **Diagnosis**: Memora determines why the previous action failed (e.g., *“Monitoring delivery vehicle via Gate 3 cameras was attempted in prior incident INC-5A208E25, but the vehicle departed before identity was verified.”*).
2. **Current Implication**: Explains why repeating the same action is contraindicated (*“Passive monitoring alone has proven insufficient to resolve this recurring vehicle pattern at Gate 3. Active verification is required.”*).
3. **Actionable Lesson**: Formulates a directive adjustment from institutional memory (*“Directive: Monitoring alone failed to identify vehicle at Gate 3. Operational adjustment: Require physical verification and supervisor notification upon arrival.”*).

## 3. Data Model Extensions

```python
class EvidenceType(str, Enum):
    CURRENT_FACT = "CURRENT_FACT"
    HISTORICAL_FACT = "HISTORICAL_FACT"
    INFERENCE = "INFERENCE"
    UNKNOWN = "UNKNOWN"
    RECOMMENDATION = "RECOMMENDATION"

class EvidenceItem(BaseModel):
    source: str
    type: EvidenceType
    confidence: float
    entity_or_location: Optional[str] = None
    supporting_record_id: Optional[str] = None
    text: str

class FailedMitigation(BaseModel):
    prior_action: str
    observed_result: str
    failure_diagnosis: str
    current_implication: str

class ActionableLesson(BaseModel):
    lesson_id: str
    historical_rule: str
    current_implication: str
    recommended_adjustment: str

class HistoricalPatternDetail(BaseModel):
    pattern_type: str
    title: str
    description: str
    supporting_record_ids: list[str]
```

All fields are fully serialized and exposed across the typed API contract (`POST /api/incidents/analyze`) and typed in the frontend client (`frontend/client/src/lib/memora-api.ts`).

## 4. Frontend Intelligence Integration

The Memora console (`frontend/client/src/pages/Home.tsx`):
1. **Analysis Output**: Displays extracted temporal window, duration, reporter, and explicit operational unknowns as dashed warning chips (`.unknown-chip`).
2. **Decision Section**:
   - Visual transformation flow (`flow-card--baseline` $\to$ `SIBYL MEMORY` $\to$ `flow-card--transformed`).
   - Failed Mitigation cards (`.intelligence-card`) diagnosing past tactical failures and current implications.
   - Actionable Operational Lesson cards (`.intelligence-card--lesson`) highlighting concrete protocol adjustments.
3. **Inference Section**:
   - Pattern badges (`.pattern-badge`) detailing detected behavioral clusters.
   - Structured evidence stack rendering typed badges (`CURRENT_FACT`, `HISTORICAL_FACT`, `INFERENCE`, `UNKNOWN`, `RECOMMENDATION`) with source attribution and confidence ratings.
